01

STEP 1 · ~15 MIN

Two tools.
Different jobs.

  • GitRecords versions of files on a computer.
  • GitHubHosts repositories online for backup and publishing.
  • RepositoryA project folder with history, not a place for secrets.

Copy these definitions into your journal in your own words.

02

STEP 2 · ~20 MIN

Open it in
VS Code.

  • UnzipUnzip your NitroIDE download into a new folder.
  • OpenIn VS Code, choose File → Open Folder.
  • Checkindex.html links style.css and script.js; give the page a real title.

Use your own free GitHub account only with parent or guardian permission.

03

GIT PATH · FIRST COMMIT

Start local
history.

git init
git add index.html style.css script.js
git commit -m "Create capstone website"
git branch -M main

Run these in VS Code: Terminal → New Terminal. Check the messages carefully before continuing.

04

GITHUB PATH · BACKUP

Send it to
your repository.

  • FollowUse the instructions GitHub shows for your new repository.
  • ProtectNever copy another person’s token, key or password.
  • PushBack up at the end of each study session.

If Git asks for credentials, use official GitHub sign-in guidance, not shared secrets.

05

STEP 3 · SMALL IMPROVEMENT

One change.
One commit.

git status
git diff
git add index.html
git commit -m "Improve project introduction"
git log --oneline

Read the diff before committing. It should show only the change you meant to make.

06

HABIT · CLEAR HISTORY

Say what
finished.

  • GoodAdd empty state to search.
  • GoodFetch questions from JSON.
  • Avoidupdate, stuff, final-final, changes.

Use a short verb phrase that would help future you understand the history.

07

IF VS CODE OR GIT IS NOT INSTALLED

You can still
keep history.

  • CreateMake the repository on GitHub.
  • UploadUse Add file → Upload files for your project.
  • EditPress . to open VS Code for the Web; commit from Source Control with a clear message.

Open commit history and compare two versions so you can explain what changed.

08

PRACTISE · ~15 MIN

History answers
what changed?

  • StatusWhat files changed now?
  • DiffWhat exact lines changed?
  • LogWhich commits were made?

If you need to restore an older version, ask a facilitator before using advanced commands.

09

STEP 5 · ~45 MIN

Your repository
must tell a story.

  • CommitsMake at least three meaningful commits.
  • OpportunitiesMove data into opportunities.json.
  • CyberSmartMove quiz data into questions.json.

fetch cannot load local JSON from file://. Keep a sample fallback until Lesson 8 deployment.

10

STEP 4 · ALWAYS

Work alone.
Stay safe.

  • Small tasksChange one feature at a time.
  • Check firstUse status and diff before every commit.
  • No secretsNo API keys, passwords, private details or personal photos.

Your repository should be something you are safe to publish if school policy allows.
