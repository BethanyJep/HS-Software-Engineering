Deployment

HOLIDAY SELF-STUDY · WEEK 4 · TUTORIAL

Put your site online.
Step by step.

Publish your capstone with GitHub Pages, test it like a visitor, then submit the showcase form.

  • TimeAbout 2–3 hours. Stop after any step and continue later.
  • ToolsVS Code (or github.dev), GitHub and GitHub Pages.
  • GoalA live, tested site and a submitted showcase form.

Do each numbered step, compare with ✅ Check, then press → for the next slide. Written guide: Lesson 8 · Showcase guide.

01

STEP 1 OF 9 · VS CODE

Check before you publish.

  1. Your home page is called index.html (all lowercase) and sits in the top folder.
  2. Every file name in your code matches the real file exactly. Capital letters matter online.
  3. Images use paths like images/club.jpg, not C:\Users\….
  4. Press Ctrl+Shift+F and search for password, key and token. Remove anything private.

good vs broken

✅ <img src="images/club.jpg" alt="Coding club">
❌ <img src="C:\Users\me\Desktop\club.jpg" alt="">

✅ fetch("questions.json")
❌ fetch("Questions.json")   (the file is questions.json)

✅ Check: all names match, and nothing private is in your files.

02

STEP 2 OF 9 · TERMINAL

Push the latest version.

  1. Open Terminal → New Terminal in VS Code.
  2. Run the four lines.
  3. Run git status once more.

terminal

git status
git add .
git commit -m "Prepare site for deployment"
git push

✅ Check: nothing to commit, working tree clean, and GitHub shows your latest commit.

Using github.dev? Open Source Control and click Commit & Push.

03

STEP 3 OF 9 · GITHUB.COM

Turn on GitHub Pages.

  1. Open your repository on github.com.
  2. Click Settings (top tabs), then Pages (left menu).
  3. Under Build and deployment, choose Deploy from a branch.
  4. Choose branch main and folder / (root), then click Save.
  5. Wait 1–5 minutes, then refresh the page.

✅ Check: “Your site is live at https://your-name.github.io/your-repo/”.

Screens look different? Follow the GitHub Pages quickstart.

04

STEP 4 OF 9 · BROWSER

Open it like a visitor.

  1. Click Visit site and copy the address.
  2. Paste it into a private (incognito) window.
  3. Do the main task on your page.
  4. Press F12 and open Console. Look for red errors.

✅ Check: the page loads without signing in, and your JSON data appears. fetch works now.

05

STEP 5 OF 9 · BROWSER

Test at phone size.

  1. With DevTools open, press Ctrl+Shift+M for the device toolbar.
  2. Choose a phone, such as a width of 375.
  3. Do the main task again, then search for something that does not exist.
  4. Close DevTools and use only Tab and Enter.

✅ Check: nothing is cut off, buttons are easy to tap, and status messages appear.

06

STUCK? · COMMON FIXES

Find the first clue.

  • 404 “There isn’t a GitHub Pages site here”Wait 5 minutes. Check Pages uses main and / (root), and index.html is in the top folder.
  • Page loads but has no stylesCheck href="style.css" matches the file name exactly.
  • Data does not loadOpen DevTools → Network. A red 404 means the file name or capital letters are wrong.
  • Old version still showingCommit and push, wait a minute, then press Ctrl+Shift+R.
07

STEP 6 OF 9 · HOME TEST

Ask someone to try it.

  1. Send your link to a family member or friend.
  2. Ask them to do one task on their phone. Do not help.
  3. Write down one problem they hit.
  4. Fix it in VS Code, then commit and push.
  5. Wait a minute and refresh your live site.

✅ Check: your fix appears on the live site.

08

STEP 7 OF 9 · README.MD

Explain your project.

  1. In VS Code, create a new file called README.md.
  2. Copy this outline and replace every line with your own words.
  3. Commit Add README and push.

README.md

# CyberSmart Quest

A quiz that helps students spot online scams.

## How to use
Open the site, read each question and choose an answer.

## Built with
HTML, CSS and JavaScript.

## Credits
Data: Open-Meteo.com. Learning: MDN Web Docs.
Images: my own photos.

✅ Check: GitHub shows your README under the file list.

09

STEP 8 OF 9 · SCREENSHOTS

Take two screenshots.

  1. Computer width: open your site full screen. Windows: Win+Shift+S. Mac: Cmd+Shift+4. Chromebook: Ctrl+Shift+Show windows.
  2. Phone width: in the device toolbar, open the ⋮ menu and choose Capture screenshot. Or screenshot on a real phone.
  3. Check that no surname, password or private detail is visible.
  4. Name them phone.png and computer.png.

✅ Check: two clear images that show what you built.

Not allowed to publish? Run the site from your folder and screenshot that instead.

10

STEP 9 OF 9 · SHOWCASE FORM

Submit your showcase.

  1. Open the Capstone Showcase Form and sign in to GitHub. Deadline: Sunday 20 December 2026.
  2. Use your first name or a nickname only.
  3. Paste your live link and your repository link.
  4. Drag both screenshots into the Screenshots box. Wait for them to upload.
  5. Answer the questions, tick the checks and submit.

✅ Check: your entry appears with a title starting [Showcase]. A facilitator will review it.

No GitHub account? Send your answers and screenshots to your facilitator. In your journal, note one feature you are proud of and one problem you solved.
