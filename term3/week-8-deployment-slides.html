Deployment

HOLIDAY SELF-STUDY · WEEK 4

Make it live.
Test it again.

Publish your individual capstone with GitHub Pages, then share it with the showcase form.

Use this with the written guide Lesson 8: Deployment and the Holiday Self-Study Pack.

Individual capstoneGrade 10 · Term 3
01

STEP 1 · ~15 MIN

From files
to users.

Edit → Test → Commit → Push → Deploy → Test again

Deployment makes software available outside your computer. Always test after publishing.

02

STEP 2 · ~30 MIN

Check before
you publish.

  • FilesHome page is index.html and links match file names exactly.
  • PathsImages and links use relative paths.
  • SafetyNo passwords, keys, private details or unlicensed images.

Also test the main task with a keyboard and at phone width.

03

PREP · QUALITY CHECK

No blank screens.
No broken phones.

  • LoadingUsers know data is being fetched.
  • EmptyNo results still explains what happened.
  • ErrorAPI failure does not break the whole page.

Resize to phone width and make sure the main action still works.

04

STEP 3 · SETTINGS

Turn on
Pages.

  • SettingsOpen Settings → Pages in your repository.
  • SourceChoose Deploy from a branch.
  • BranchSelect main and / (root), then save.

GitHub labels can change; use the GitHub Pages quickstart if screens look different.

05

AFTER DEPLOY · ~15 MIN

Open like
a visitor.

  • WaitGive GitHub a few minutes to build.
  • PrivateOpen the URL in a private or incognito window.
  • NavigateTry the main path without signing in.

If the public page works, copy the live link for your showcase evidence.

06

WHEN IT FAILS

Find the
first clue.

  • PagesIs Pages enabled for the correct branch and folder?
  • IndexIs index.html at that location?
  • ConsoleDo Console or Network show missing files or errors?

Capital letters matter online: Questions.json and questions.json are different files.

07

STEP 5 · HOME TEST

Ask someone
to try it.

  • TesterSend the URL to a family member or friend.
  • PhoneAsk them to try the main task on a phone.
  • FixCommit one issue they found and confirm it appears online.

The site should load without sign-in and show no private information.

08

STEP 6 · DOCUMENT

Explain your
project.

  • PurposeWhat problem does the capstone solve?
  • HowHow should someone use it?
  • CreditsList data, learning resources and permitted images.

A short README helps reviewers understand and credit your work correctly.

09

POLISH · ~30 MIN

Prepare proof
it works.

  • ProudChoose one feature to show in a screenshot.
  • ProblemWrite one deployment issue you solved.
  • ImproveList one final improvement before showcase.

If publishing is not approved, take screenshots of it running locally instead.

10

HOLIDAY PACK · CHECKLIST

Save your
evidence.

  • Live linkYour GitHub Pages URL or local files.
  • ScreenshotsOne phone-width and one computer-width screenshot.
  • JournalCompleted Lessons 5–8 journal and one feedback improvement.

Finished is better than perfect: a small project that works and that you can explain matters.

11

FINAL · CAPSTONE SHOWCASE

Submit your
showcase form.

  • IncludeLive link, or a note that it runs locally.
  • AttachPhone-width and computer-width screenshots.
  • CheckNo passwords, API keys or personal private details are visible.
